# RESET LBVI — how to run the model (GUI, single run, or batch/sweep)

Put **everything in one folder**. All three ways of running the model then work with
no path editing. Recommended layout (the folder name is up to you, e.g. `C:\RESET`):

```
RESET/
├── RESET_LBVI.jar                 # the model (rename your built jar to this,
│                                  #   or edit "jar" in sweep_config.json)
├── RESET_LBVI_inputData/          # all input files, incl. the beetle scenarios
│   ├── RESET_merge_final.shp      #   (+ .dbf / .shx / .prj / ...)
│   ├── inTerritories2020.csv
│   ├── inGroundwaterBAU.csv
│   ├── inCowbirdTrapsRecent2020.csv
│   ├── inVireoPopulation2020.csv
│   ├── inBeetleImpact_Pendleton.csv
│   ├── inBeetleImpact_SantaClaraCentral.csv
│   └── inBeetleImpact_SantaClaraEast.csv
├── paramListDefault.csv           # baseline: ALL model parameters live here
├── run_sweep.py                   # batch/sweep runner (sweep only)
└── sweep_config.json              # batch/sweep settings (sweep only)
```

## Prerequisites (install once)

| Tool | Needed for | Notes |
|---|---|---|
| **Java** | all three modes | the same Java you already use for the GUI |
| **Python 3.7+** | batch/sweep only | standard library only, no extra packages. Command is usually `python` on Windows, `python3` on Mac/Linux |

## The three ways to run

Run the command from **inside the folder** shown above.

| Mode | Command | Needs in the folder |
|---|---|---|
| **GUI** (click-run) | `java -jar RESET_LBVI.jar` | `RESET_LBVI.jar`, `RESET_LBVI_inputData/` |
| **Single headless** (one run, no window) | `java -cp RESET_LBVI.jar lbvi.LBVIEnvironment -paramFile paramListDefault.csv -seed 42` | `RESET_LBVI.jar`, `RESET_LBVI_inputData/`, `paramListDefault.csv` |
| **Batch / sweep** (many runs) | `python run_sweep.py` | `RESET_LBVI.jar`, `RESET_LBVI_inputData/`, `paramListDefault.csv`, `run_sweep.py`, `sweep_config.json` |

**Notes**

- **GUI:** after it opens, set `paramFilePath` to `paramListDefault.csv` in the **Model tab**, then press **Play**. (The GUI needs a desktop/screen — it will **not** open on a headless server; use headless or sweep mode there.)
- **Single headless:** add `-outputDir runs/myRun` to send that run's outputs to their own folder.
- **Batch/sweep:** preview first with `python run_sweep.py --dry-run` (prints the commands; writes and runs nothing).

## Batch / sweep — one-time setup

1. **Use the portable config.** Copy `sweep_config_portable.json` into this folder and **rename it to `sweep_config.json`** (that's the name `run_sweep.py` looks for). All its paths are relative, so no editing is needed if the layout above is used.
2. Make sure `"jar"` in `sweep_config.json` matches your jar's filename (default: `RESET_LBVI.jar`).
3. Preview, then run:
   ```
   python run_sweep.py --dry-run     # prints the commands; writes/runs nothing
   python run_sweep.py               # actually runs them
   ```

## Where parameters are set

- **All model parameters live in `paramListDefault.csv`** (one `parameter,value` row each). This is your single source of truth for every run, GUI or sweep.
- `sweep_config.json` only lists what the **batch** changes:
  - `"sweep"` — parameters to vary (each a list, or `{"range":[start,stop]}`).
  - `"fixed"` — values held constant for every run in the batch.
- **Precedence per run** (lowest → highest): `paramListDefault.csv` → `fixed` → swept value.

## Common edits in `sweep_config.json`

| Setting | What it controls |
|---|---|
| `beetleImpactFilePath` | which beetle scenario: `RESET_LBVI_inputData/inBeetleImpact_Pendleton.csv`, `…_SantaClaraCentral.csv`, or `…_SantaClaraEast.csv` |
| `sweep` + `mode` | which runs happen. Default = the 100 PSHB replicates (`mpBeetleRunNum` 1..100). `"full_factorial"` = every combination of all swept values; `"one_at_a_time"` = vary one at a time from the first (baseline) value |
| `parallel_jobs` | how many runs at once |
| `heap` | memory per run (`-Xmx`) |

> **RAM rule:** keep `heap × parallel_jobs` below your machine's RAM, leaving a few GB for the OS. Lower `parallel_jobs` on a smaller machine; raise `heap` if a run reports `OutOfMemory`.

## Where results go

Each run writes to its own folder, `runs/<runId>/`:

| File | Contents |
|---|---|
| the usual output CSVs | `logReproductivePerformance.csv`, `logMortalityEvents.csv`, … |
| `params.csv` | the exact parameters that run used (generated by `run_sweep.py`) |
| `paramList.csv` | the model's own full parameter snapshot |
| `stdout.log` | that run's console output |

- Index of every run → its parameters: `runs/sweep_manifest.csv`
- Overall console log: `runs/sweep_run.log`
